# 用照片尋找餐廳（找餐廳 & 這哪家 Discord 機器人）

這個專案結合大語言模型、視覺多模態與本機自動化瀏覽器，能根據使用者上傳的餐點照片，找出最可能的餐廳店家，並以近期 Google Maps 照片、菜單評論、地址和即時營業狀態進行多重物證核對。

---

## 🐾 「這哪家」Discord 美食偵探機器人

專案內建了 Discord 機器人模組（位於 `discord_bot/`），讓伺服器成員直接在頻道中傳照片尋找餐廳。

### 🌟 核心特色
- **純直覺觸發**：發布照片時在內文標註 `@這哪家`，或引用回覆歷史照片並標註 `@這哪家`，即可自動啟動排查。
- **全自動獨立對話接軌**：當遇到疑難照片時，機器人會自動於 `案件/` 建檔，並調用本地 Antigravity 底層 API，在專案內開啟全新的獨立對話（以極省 Token 的 `Gemini Flash` 執行），完成後自動回傳 Discord。
- **群友競猜互動**：支援群友在討論串或頻道猜店名，若搶先答對，機器人會為該訊息加上 `🎯` 表情認證，並通報群友搶先獲勝。
- **簡約狀態表情（同一時間單一 Emoji）**：
  - `🔍`：正在秒查與檢索特徵
  - `🕵️`：已進入 Antigravity 深度微型物證排查
  - `✅`：成功破案結案（附上 Google Maps 導航連結）
  - `❓`：達到 30 分鐘停損原則，線索不足以確認

### 🚀 快速安裝與啟動

1. **安裝依賴套件**：
   ```bash
   pip install discord.py
   ```
2. **配置私密設定檔**：
   - 複製 `discord_bot/config.json.example` 為 `discord_bot/config.json`：
     ```bash
     cp discord_bot/config.json.example discord_bot/config.json
     ```
   - 編輯 `discord_bot/config.json`，填入您的 Discord Bot Token 與 Google Gemini API Key：
     ```json
     {
       "bot_token": "YOUR_DISCORD_BOT_TOKEN_HERE",
       "gemini_api_key": "YOUR_GEMINI_API_KEY_HERE",
       "trigger_timeout_seconds": 180,
       "reply_footer": "(此為貓貓自動偵測回覆)"
     }
     ```
     > [!IMPORTANT]
     > `config.json` 已預設加入 `.gitignore`，包含所有金鑰與敏感資訊，絕對不會被提交或推送到 GitHub。

3. **啟動機器人**：
   ```bash
   python discord_bot/bot.py
   ```

## 🤖 給 AI 的開始方式

若 AI 會讀取專案指示，先讀取根目錄的 `AGENTS.md` 和 `找餐廳判斷規則.md`。之後使用者只要上傳餐點或店內照片，即開始餐廳辨識；除非使用者另有要求，不必先問「要我做什麼」。

若 AI 不會自動讀取專案檔案，可在對話中貼上以下任務說明，並附上照片：

> 請依此專案的 `找餐廳判斷規則.md` 分析我附上的照片，辨認最可能的餐廳。請先核對照片中的餐點、餐具、桌面與店內環境，再以圖片搜尋及 Google Maps 近期照片、評論、地址和目前營業狀態驗證。若我沒有指定日期，預設找目前仍營業的店；若地點未指定，使用規則中的預設搜尋範圍，必要時擴大並註明。請把本次照片建成獨立案件，記下我的後續更正與已排除店家。結論必須提供店名及可開啟的 Google Maps 地點連結；證據不足時要明確說尚無法確認，不可猜成定論。

## 📁 專案內容結構

- `AGENTS.md`：AI 接手本專案時的操作指引（含 Chrome 9222 就地控制器、全自動獨立對話與 30 分鐘時間控制規範）。
- `找餐廳判斷規則.md`：比對方法、進階破案技巧（局部裁切、微型物證提取、記憶偏差雙軌驗證）、查證標準和輸出格式。
- `discord_bot/`：Discord「這哪家」機器人核心模組（含照片感應、群友猜題追蹤、疑難案件自動建檔）。
- `scripts/browser_controller.py`：AI 專用 Chrome（`Port 9222`）就地控制與 Google Lens 多模態以圖搜尋 CLI 工具。
- `案件/案件模板.md`：每張新照片／每個新辨識任務的紀錄模板。
- `案件/`：歷史辨識案件（如案件 001～009）的觀察、紀錄、照片與排除名單。

## ⚠️ 使用時的注意事項

- **個案獨立原則**：每張不同照片建立新案件；只有使用者說是在延續同一張照片／案件時，才更新舊案。個案中的店名、地點、餐點、排除名單不可帶到新案件。
- **時效性與營業狀態核查**：搜尋不到近期 Google 資料時，降低把握度；不要把舊食記當成仍在營業的證據。
- **客觀交代限制**：如果 AI 無法上網或使用圖片搜尋，應說明缺少哪種查證能力，並先完成可做的照片觀察，不可假稱已核實。
